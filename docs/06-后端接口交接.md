# 后端接口交接

后端采用 `/api/v1`、JSON snake_case、UUID 和 UTC Unix 毫秒业务时间。导入导出及备份清单中的 `created_at` 使用 UTC RFC3339 字符串。本文说明当前实现的调用方式，原始需求仍见 01—05。前端应用、编辑器 UI、IndexedDB 草稿和浏览器自动保存由后续前端实现。

## 请求与响应

`GET /health` 返回 `instance_id`、`data_epoch`、版本、维护状态和生效限额。所有写请求携带 `X-Data-Epoch: <data_epoch>`，缺失或过期均返回 `409 DATA_EPOCH_CHANGED`。JSON 写请求用 `Content-Type: application/json`；未知字段拒绝。创建请求可带 `Idempotency-Key`；同一路径同键同正文重试得到已提交响应，不同正文返回 `409 IDEMPOTENCY_KEY_REUSED`。建议创建和所有任务提交都使用键，并保留原始请求 JSON 字节。

已受理的 `/backups/restore` 有重放例外：同键同正文重试在维护与世代检查之前返回原 `job_id` 和当前任务状态，允许恢复提交响应丢失后使用旧世代头查询，不启动新恢复。其它过期写请求仍拒绝。

```json
{"data":{"id":"UUID"},"meta":{"tree_revision":2}}
```

```json
{"error":{"code":"REVISION_CONFLICT","message":"文档已由其他编辑会话更新","details":{"revision":3}},"request_id":"UUID"}
```

列表 `data` 为数组，`meta` 含 `page`、`page_size`、`total`。默认 20，最大 100。参数从 1 开始。详情 `data` 为对象；无数据列表为 `[]`。

## 知识库、树和正文

| 方法 | 路径 | 请求正文 / 结果 |
|---|---|---|
| GET / POST | `/knowledge-bases` | 分页列表 / `{name,description?}` 创建，201 |
| GET / PUT | `/knowledge-bases/{id}` | 详情 / `{name,description}` 更新 |
| DELETE | `/knowledge-bases/{id}` | `{expected_tree_revision}`，整库移入回收站 |
| GET | `/knowledge-bases/{id}/tree` | `data.nodes` 嵌套元数据树，树版本随响应返回；无正文 |
| POST | `/knowledge-bases/{id}/documents` | `{parent_id,title?,markdown?,expected_tree_revision}`，201；根节点必须显式 `null` |
| GET / PUT | `/documents/{id}` | 详情 / `{title,markdown,expected_revision,snapshot?}` 保存 |
| DELETE | `/documents/{id}` | `{expected_tree_revision}`，有效子树按批次软删除 |
| GET | `/documents/{id}/status` | `active` / `trashed` / `missing`，回收站批次 ID；不给回收站正文 |
| GET | `/documents/{id}/history` | 分页历史摘要 |
| GET | `/documents/{id}/history/{history_id}` | 历史标题、正文、revision |
| POST | `/documents/{id}/history/{history_id}/restore` | `{expected_revision}`，恢复前快照，返回新的 revision |

详情包含 `id`、`knowledge_base_id`、`parent_id`、`title`、`markdown`、净化后的 `html`、`render_version`、`revision`、排序和时间。新建标题缺省为“无标题”。标题同名允许。正文上限 10 MiB，标题上限 200 Unicode 字符，树最大 32 层，每库最多 10000 个有效节点；创建、导入和恢复超限整批拒绝。HTTP JSON 上限 61 MiB，允许最大正文转义后的传输开销，正文仍独立按 UTF-8 字节限制。

标题重命名同样通过正文保存接口，必须提交当前正文及基础 revision。客户端不能提供 HTML、索引正文或附件引用列表。`409 REVISION_CONFLICT` 的详情提供当前 revision、标题、时间和正文摘要；完整正文重新 GET。不能自动修改 expected_revision 后覆盖。手动保存 `snapshot:true` 强制保存旧版本快照；自动快照为 5 分钟窗口，默认最多 100 条。

树的 `tree_revision` 与正文 revision 分开；创建、删除、恢复和标题变化会改变树版本。同库移动、拖拽排序及跨库移动是 P1，首版不注册 position 接口。父节点可有正文和子节点，节点排序为 sort_order、id。

内部链接为 `/documents/{document_uuid}`。前端路由使用 UUID；链接目标 404 时可请求 `/status` 区分回收站与永久删除。

## 回收站和附件

| 方法 | 路径 | 请求正文 / 结果 |
|---|---|---|
| GET | `/trash` | 分页批次，支持 knowledge_base_id |
| GET | `/trash/empty-preview` | 全部有效批次的去重影响范围 `delete_preview` 及 `confirmation_token` |
| DELETE | `/trash` | `{confirmation_token}`，单事务清空全部有效批次，返回删除批次/文档/历史统计及附件清理候选 |
| GET | `/trash/{batch_id}` | 批次节点、永久删除影响预览、confirmation_token |
| POST | `/trash/{batch_id}/restore` | `{expected_tree_revision}`，只恢复该批次；返回位置调整 |
| DELETE | `/trash/{batch_id}` | `{confirmation_token}`，返回永久删除统计及附件清理候选 |
| POST | `/attachments` | multipart 单个 `file` 字段，201，返回 id、url、state |
| GET | `/attachments` | 分页列表，可 `filter=unreferenced` / `filter=missing` |
| GET | `/attachments/{id}` | 元信息、state、当前/历史/回收站引用数 |
| GET / HEAD | `/attachments/{id}/content` | 文件读取；可用图片内联，其余附件强制下载 |
| POST | `/attachments/cleanup-preview` | `{attachment_ids:[UUID...]}`，引用摘要及 confirmation_token |
| POST | `/attachments/cleanup` | `{attachment_ids,confirmation_token}`，202 返回 task_ids |

附件正文 URL 固定为 `/api/v1/attachments/{id}/content`。上传最大 50 MiB，按实际类型判断，HTML/SVG/未知类型强制下载。上传成功后正文仍须单独保存。当前正文、历史和回收站引用均阻止清理。永久删除文档不直接删文件。

确认令牌有效期 10 分钟，绑定预览内容；重启或内容变化后需重新预览。先恢复所属知识库，再恢复独立文档批次。原父失效时根节点改挂知识库根层并返回原因。永久删除整库会包含此前独立删除的批次，预览展示实际范围。清空回收站使用整体预览，包含全部分页中的有效批次，知识库及其独立文档批次合并计算，避免重复计数。提交先验证整体确认令牌，再在一个事务内执行；预览过期或内容变化时返回 `409 CONFIRMATION_EXPIRED`，执行失败整批回滚，不会只删除部分批次。

附件清理受理后的状态为 pending_delete，阻止下载与新增引用；后台任务最终将其置为 deleted。调用 `/attachments/{id}` 查询最终状态，不能把 202 当作已完成。失败任务会有界退避并在重启后继续。未绑定附件不会自动清理，前端须提示先处理浏览器草稿。

## 检索

`GET /search?q=...&knowledge_base_id=...&page=1&page_size=20`。关键词上限 200 Unicode 字符。普通查询按字面词项处理，英文用 FTS5，中文短词及符号用转义 LIKE 回退。结果去重，标题精确/包含优先，再按 FTS 相关性、时间与 ID 排序。响应 meta.search_mode 显示实际路径。

结果包含 `document_id`、知识库 ID/名称、标题、纯文本 `snippet`、`highlights`、`title_highlights`。高亮为 Unicode 码点 `[start,end)`，前端先 `Array.from(text)` 再切片，勿把片段当 HTML。搜索包含代码、公式和 Mermaid 源码；正文定位由前端阅读视图完成。

## 导入、导出和任务

| 方法 | 路径 | 请求正文 / 结果 |
|---|---|---|
| POST | `/imports/preflight` | multipart 重复的 `file` 字段（多篇 .md / .markdown，或单个 .zip），返回同一预览 ID、树、资源、警告 |
| POST | `/imports/classify` | `{preview_id,source_id}`，对暂存的单篇 Markdown 返回概率最高的知识库；需开启 `import_auto_classify`，ZIP 拒绝分类 |
| POST | `/imports` | `{preview_id,target_knowledge_base_id,target_parent_id,expected_tree_revision}`，202 |
| POST | `/exports` | `{scope,id,format,include_attachments}`，202 |
| GET | `/jobs/{id}` | `state`、`progress`、`result`、`download_url` 或错误摘要 |
| GET | `/jobs/{id}/download` | 完成的导出 / 备份文件 |

任务状态为 queued / running / succeeded / failed / cancelled。以 succeeded 确认完成，轮询建议从 500ms 递增至 2s。维护期间健康与任务状态仍可查询。

预检不创建正式文档，预览 24 小时有效。提交整批新增并分配新 ID，允许同名，不覆盖既有数据。树版本过期时失败，重新确认目标并提交。普通 ZIP 目录表示树，index.md 表示父正文；产品内容 ZIP 使用 manifest 还原标题、父关系及排序。资源、内部文件链接转为新 UUID 引用。缺失本地资源整包拒绝，外链保留并报告。危险路径、符号链接、重复规范路径、超深及超限归档拒绝。

导出 scope 为 `document` 或 `knowledge_base`；format 使用 `md`（单篇纯文本）、`markdown_zip` 或 `html_zip`。include_attachments 缺省 true。导入内容 ZIP 上限 500 MiB、实际展开 1 GiB、条目 10000；导出不应用这组导入限额，较大导出包回导前需检查限额。ZIP 使用 `manifest.json`、`documents/`、`assets/`。资源导出保持 Markdown 正文不增加 H1，标题放清单；纯 .md 增加独立标题 H1。包内链接和资源改为相对路径，范围之外目标列入 unresolved_links。HTML 包含本地公式、图表、字体和样式。

导入预览增加 `source_kind`（`markdown` / `zip`），每篇文档具有稳定的 `source_id`。
独立 Markdown 支持逐篇提交：`{preview_id,targets:[{source_id,target_knowledge_base_id,target_parent_id,expected_tree_revision}]}`。
必须覆盖本次预览的全部文档，每篇只指定一个位置；不能重复或引用未知 `source_id`。
每个目标知识库单独校验树版本、父文档与容量，整批跨知识库导入仍共享新 ID 映射、链接重写和一个事务。
成功结果包含每篇的 `knowledge_base_id`、`parent_id` 与各库 `tree_revisions`；只涉及一库时保留 `tree_revision`。
ZIP 与旧客户端继续使用整包目标参数，ZIP 不允许 `targets` 拆分。

设置接口增加可读写布尔值 `import_auto_classify`（默认 false），只读 `import_classifier_configured` 表示后端密钥和根地址格式已配置，不表示服务已实际连通。
分类请求读取完整暂存 Markdown，服务地址通过 `LJMDB_DECISION_BASE_URL` 配置，环境变量见部署说明。
分类成功返回 `{source_id,target_knowledge_base_id,target_parent_id:null,probability,confidence}`。
不使用置信度阈值，始终选择最高概率的一个知识库；失败不会改变导入内容或位置，客户端可继续手动选择。

## 完整备份、恢复和设置

| 方法 | 路径 | 请求正文 / 结果 |
|---|---|---|
| POST / GET | `/backups` | 创建完整备份任务，202 / 分页备份列表 |
| POST | `/backups/validate` | multipart 备份 `file` 或 JSON `{backup_id:已完成备份任务ID}`，返回校验预览及确认令牌 |
| POST | `/backups/restore` | `{validated_backup_id,confirmation_token}`，202，建议必须带幂等键 |
| GET / PUT | `/settings` | 设置及只读数据目录/限额 / `{locale?,timezone?,theme?,history_limit?,confirm_history_reduction?}` |
| GET | `/health` | 数据集合标识、世代、版本、可写/维护状态、限额 |
| POST | `/maintenance/rebuild-index` | 重建 HTML/检索缓存与 FTS，不改变正文 revision/history |
| POST | `/maintenance/check-integrity` | 检查数据库、外键、树及 FTS；发现损坏停止该操作并提示恢复 |

完整备份使用 VACUUM INTO 一致快照，暂停写入和物理清理，校验数据库及所有保留附件，含历史、回收站与设置；不套用普通内容 ZIP 500 MiB 限额。恢复预检哈希、schema、数据库/FK/树/附件完整性，确认后生成恢复前完整备份，停写关库并分阶段切换。切换日志在 runtime，任务查询和同键恢复重试能跨数据库替换工作。

完整恢复保留 instance_id 和所有实体 ID，重新生成 data_epoch。成功 result 含 `reload_required:true`，浏览器必须重载并人工处理旧草稿。恢复失败会回退；若回退也失败，保持维护停写。备份和导出不包含浏览器草稿。

语言、时区、主题默认分别为 `zh-CN`、`Asia/Shanghai`、`auto`，保存在数据库中并随完整备份迁移。设置允许部分更新；当前语言仅支持 `zh-CN`，时区使用 IANA 名称，主题为 `auto` / `light` / `dark`。时区影响界面时间显示；API 的 Unix 毫秒与导出清单的 UTC 时间约定保持一致。

history_limit 为 1—1000。降低上限需 `confirm_history_reduction:true` 并删除超额历史及引用；增加不恢复已清除快照。数据目录/监听地址通过 CLI 修改，需要重启。

Host 仅允许指定回环服务；写请求 Origin 必须与服务同源，cross-site 拒绝。API 不开放通配 CORS。前端开发代理需要同步改写 Host 与 Origin 到后端地址，或在同源部署后验证；不要直接从另一个端口发跨源写请求。构建完成后使用 `--web-dir` 同源提供页面，或通过 `App.FrontendFS` 嵌入资源；不存在的 API 始终返回 JSON 404，不回退到 SPA。
