## 容量与离线导出

容量样本包含 10000 篇文档，每篇 20489 字节，三个查询均命中全部文档。通过 HTTP handler 测量服务端处理时间；每个查询发出 6 次请求，记录最慢值，不将这一小样本称为稳定 P95 或冷热缓存对照。

| 场景 | 测量结果 |
|---|---|
| 英文 `Markdown` | 最慢 869.93 ms |
| 中文 `中文短词` | 最慢 756.11 ms |
| 字面 `%` | 最慢 1124.94 ms |
| 10000 节点元数据树 | 576.59 ms；响应约 1.58 MB |
| 约 100 KB 正文，20 次实际变化保存 | P95 54.09 ms；最大 59.62 ms；保留 FULL 同步及真实事务 |

这些是当前 Linux arm64 主机上的服务端证据。测试机约 15 GiB 内存，与设计参考的 8 GB 环境不同；没有测量浏览器树渲染、冷启动缓存和其它目标机器，不能把结果泛化为所有平台的性能保证。

离线 HTML 专项生成资源 ZIP、解压后用真实 `file://` 打开：2 个公式、2 个 Mermaid 图、本地图片、代码高亮、重复标题不同锚点及 KaTeX 字体均通过；HTTP 请求 0，渲染错误 0，页面异常 0。测试未开发或依赖应用前端。

复现专项：

```bash
LJMDB_RUN_PERF=1 go test ./internal/backend -run '^TestBackendPerformance$' -count=1 -v

# 指向已安装的 Playwright；此路径为本次工作区外的测试安装。
LJMDB_PLAYWRIGHT_MODULE=/tmp/ljmdb-browser-acceptance/node_modules/playwright \
LJMDB_BROWSER_TESTS=1 go test ./internal/backend \
  -run '^TestOfflineHTMLExportInBrowser$' -count=1 -v
```

`scripts/build.sh` 使用 `CGO_ENABLED=0` 生成六个平台二进制，附带 SHA256SUMS、第三方授权与本地导出资源。已核对 Linux ELF、macOS Mach-O、Windows PE 的目标架构。Linux arm64 最终本机二进制通过真实 HTTP smoke。

## 升级失败与恢复操作

已有可信迁移记录的数据库升级前，程序用 `VACUUM INTO` 生成 `<data-dir>/backups/pre-upgrade-<uuid>/knowledge.db`。快照生成后若启动失败，错误中附带该恢复路径，程序不返回可写数据库；迁移失败测试核对原记录、版本及快照完整性。

优先使用已验证的完整备份恢复。若需手工使用升级前数据库快照：先确认程序已正常退出、目录锁释放；完整归档保留当前数据目录，再制作恢复用副本。在恢复副本的活动目录中移走旧 `knowledge.db-wal` / `knowledge.db-shm`，然后用快照替换 `knowledge.db`；原数据库及其 WAL/SHM 保留在归档中，不能与替换后的数据库混用。附件和其它目录保持配套，用兼容该 schema 的程序在副本上启动并检查完整性。数据库快照只回退数据库，不替代包含附件的完整备份。

旧程序发现更高的 schema 或不一致的迁移记录会拒绝写入。恢复成功保留 instance_id、改变 data_epoch；浏览器应重载并人工处理旧草稿，不能仅更新世代头后重发旧正文。
