# 开发计划与验收标准

版本：v1.0；日期：2026-10-04；状态：待实施计划，未执行验收。

本文将 [产品需求](01-产品需求与功能规格.md) 转换为实施顺序和发布标准。任何测试目标和性能指标均为待验证要求，不表示现有项目已经具备功能或通过测试。

## 1. 实施原则与交付分级

先验证离线运行、SQLite 构建、渲染和中文检索，再实现可信赖的保存及恢复，最后完善整理效率。不要先把三种编辑模式全部开放，再补数据保护。

| 阶段产物 | 使用范围 | 进入下一阶段的条件 |
|---|---|---|
| 技术原型 | 使用可丢弃测试资料验证选型 | 关键风险有实际样例和目标平台证据 |
| 内部可用版本 | 用合成数据和可恢复副本试用 | 核心流程与失败路径完成，但不作为唯一资料存储 |
| 第一版正式可用 | 单机个人长期使用 | P0 功能、备份恢复、迁移及关键故障场景全部通过 |
| 后续增强版 | 改善组织、检索和访问体验 | 新增能力保留既有数据可靠性保证 |

本文不承诺具体开发天数。工作量取决于目标平台、参与人数及原型结果；排期时使用下面的依赖和阶段门，不把探索工作当作确定工期。

## 2. 阶段 A：技术验证与选型

目标：把高风险描述转换为可运行的小实验。

| 工作编号 | 工作内容 | 完成证据 |
|---|---|---|
| A-01 | 确认 SQLite 驱动、FTS5 和备份能力 | 创建 FTS 表、写入查询、删除恢复、生成并打开快照 |
| A-02 | 目标平台 Go 打包 | 无额外服务的目标系统启动截图与构建记录 |
| A-03 | Vditor / Lute 版本及渲染契约 | 固定语料编辑往返、阅读与标题锚点比较 |
| A-04 | 离线资源验证 | 断网首次启动，公式、Mermaid、字体与高亮无外部请求 |
| A-05 | 中文基础搜索原型 | 两字词、长句、中英混合、代码词和符号的结果记录 |
| A-06 | HTML 导出原型 | 另一目录或设备用文件方式打开，图片、公式和图表可见 |
| A-07 | 数据目录、锁和退出 | 只读目录、端口占用、双实例、正常退出处理记录 |

对照候选驱动测试实际发行产物，不能只验证开发机。目标平台列表与最低版本在本阶段明确；计划支持 Windows、macOS、Linux 的每一项，都需有独立证据。

阶段门：关键能力不成立时先调整依赖或范围并更新文档。不得带着“以后应该能解决”的离线资源或备份缺口进入正式版本承诺。

## 3. 阶段 B：工程骨架与文档组织

目标：获得可保存、读取和组织测试资料的最小闭环。

实施内容：

1. 初始化 Go、Vue 3、TypeScript、Vite、路由与状态管理，配置依赖锁定和构建流程。
2. 建立服务层、数据库事务入口、结构迁移、统一错误响应和健康接口。
3. 实现系统数据目录、可选便携模式、文件锁、回环地址绑定和优雅退出。
4. 实现知识库列表、新建、修改，文档新建、详情、标题及父子结构读取。
5. 文档树只读取元数据；创建时校验父节点存在、同库、最大深度和默认排序。
6. 落实稳定 UUID 路由，健康接口提供数据集合 instance_id。

阶段门：数据库重启后读写正确；结构升级可回滚；坏父节点与超深结构不能进入数据库；界面错误不创建另一套空数据。此时暂不使用永久删除作为便捷开发手段。

对应需求：FR-001、FR-002、FR-003 的骨架，以及 FR-011、FR-012 的基础。

## 4. 阶段 C：编辑、可靠保存和恢复

目标：持续写作时明确知道哪些内容已提交，异常后能找到本地草稿。

实施内容：

1. 集成一个稳定 Vditor `ir` 模式，完成标题、正文、只读阅读和大纲。
2. 实现 3 秒防抖、30 秒最长间隔、手动保存与每文档串行保存队列。
3. 将请求快照和编辑器最新内容分开，响应不会把后续输入误标为已保存。
4. 保存使用 expected_revision 条件更新，冲突返回 409；树内重命名也遵守版本规则。
5. 实现实例及编辑会话作用域 IndexedDB 草稿、写入失败提示、恢复比较和另存为新文档。
6. 实现退避重试与暂停状态，区分临时故障、校验错误、维护状态和冲突。
7. 引入历史快照与附件引用结构，避免稍后添加历史时重做保存事务。
8. 对预览及阅读 HTML 净化，代码和搜索片段正确转义。

阶段门：两个标签页、慢请求、响应丢失、连续输入、服务退出和草稿存储失败有可验证结果。关闭页面只能作为尽力保存，不能以成功收到关闭事件作为数据已落盘的证据。

对应需求：FR-004、FR-005、FR-008 的历史基础。

## 5. 阶段 D：附件、回收站和历史闭环

目标：内容引用、删除与恢复不会损坏其他资料。

实施内容：

1. 文件选择、图片粘贴与拖入，上传暂存、类型判断、原子改名与元数据提交。
2. 稳定附件 ID 和下载路由；主动内容默认下载，不直接执行。
3. 从 Markdown 提取本地附件引用，更新当前正文与历史引用关系。
4. 文档子树与知识库按批次软删除，正常树与搜索排除已删除内容。
5. 整批恢复、失效父节点回根、先恢复知识库、明确永久删除语义。
6. 历史查看、比较和恢复，默认最多 100 条；恢复前强制保留当前版本。
7. 未引用附件候选清理，人工确认后重新校验并标记 pending_delete，再执行可重试物理删除。
8. 重启处理上传孤立文件和未完成清理任务，失败不得伪装成全部完成。

阶段门：复制正文复用图片后删除原文，另一文档仍可显示；旧历史和回收站资源可恢复；数据库和文件操作中途失败可恢复到一致状态。

对应需求：FR-006、FR-008。

## 6. 阶段 E：搜索、内部链接与数据流转

目标：资料可以找到、迁入和离开应用使用。

实施内容：

1. FTS 外部内容和触发器，初始化 rebuild，标题权重及中文 LIKE 回退。
2. 搜索范围、分页、字面特殊字符、结果去重与安全片段。
3. 搜索进入阅读页后高亮及上一处/下一处；无法定位时明确说明。
4. 内部链接选择器，按 UUID 跳转，回收站与失效链接提示。
5. Markdown / ZIP 导入预检、预览、分配新 ID、树和资源链接重写、事务提交。
6. 单篇、知识库 Markdown 资源 ZIP 与 HTML 资源 ZIP；处理父文档正文、同名和非法路径。
7. 导入重复请求和响应丢失可查询原任务状态；不把同名标题当成覆盖授权。

阶段门：本产品导出包在空库重新导入可保留正文、标题、树关系、内部链接和本地资源；解压到另一台断网设备仍可阅读。内容导入创建新 ID，完整备份恢复保持旧 ID，必须分别验证。

对应需求：FR-007、FR-009、FR-010、FR-012。

## 7. 阶段 F：备份、恢复与正式发行

目标：故障和升级后能恢复完整应用状态。

实施内容：

1. 在线备份维护状态，暂停写入及物理清理，等待在途操作后生成一致快照。
2. 数据库和不可变附件打包，manifest、校验和、生成失败处理。
3. 恢复预检，覆盖前回退备份，停写关库、分阶段切换、重开校验与失败回滚；切换日志独立于待替换数据库，并生成新 data_epoch。
4. schema 版本自动迁移、升级前备份、旧程序拒绝新 schema。
5. 系统数据目录、设置、启动和退出提示、日志轮转与资源限制。
6. 每个平台发行文件、校验和、依赖授权、完整离线演练与使用说明。

阶段门：完成全部 P0 验收，恢复一次真实测试备份并逐项对比；不能仅验证备份包能下载。单机免登录安全边界已落实，首版不开放未经设计的非回环监听。

对应需求：FR-001、FR-011 及全部正式发行约束。

## 8. 后续迭代

| 迭代 | 能力 | 额外验收 |
|---|---|---|
| P1 组织效率 | 拖拽、同库挂接、跨库移动与复制 | 无环、整树深度、事务排序、附件与链接不丢 |
| P1 写作体验 | 最近访问、收藏、主题、其他编辑模式 | 数据往返无损、模式转换语料、键盘等价操作 |
| P2 知识关联 | 标签、反向链接 | 索引一致性、删除恢复、跨库检索 |
| P2 搜索增强 | 真正中文分词、更强筛选 | 索引与查询同策略、词典打包、短词召回、rebuild |
| P2 局域网 | 显式启用、密码哈希、会话、TLS | 附件鉴权、CSRF、登录限速、接口隔离 |
| 独立项目 | 多用户、同步、协作、AI、OCR | 重新定义数据与权限边界，不沿用单机假设 |

## 9. 验收案例

下表属于必须执行的案例集，执行后记录实际结果、环境和证据。网络、磁盘和进程故障应在可恢复的合成数据环境中注入。

| 编号 | 关联需求 | 场景与步骤 | 通过标准 |
|---|---|---|---|
| AT-001 | FR-001 | 断网首次运行，打开公式、Mermaid、代码与图片 | 不发起必要的 CDN 请求，功能可用 |
| AT-002 | FR-001 | 端口占用、只读目录、同目录重复启动 | 明确原因，不杀其他程序、不生成隐蔽空数据库 |
| AT-003 | FR-002/003 | 同名库与文档，创建 32 层，继续创建第 33 层 | 同名可区分，超深操作拒绝，数据库无非法节点 |
| AT-004 | FR-004 | 固定 Markdown 语料加载、编辑、保存、再打开 | 正文无意外修改，扩展渲染和大纲正确 |
| AT-005 | FR-005 | 连续输入 90 秒，再停止 3 秒，保存中继续输入 | 按最长间隔触发；成功响应只确认对应快照 |
| AT-006 | FR-005 | 保存时暂停后端，继续编辑并重开页面 | 自动重试有界，本地草稿可见，未声称服务端成功 |
| AT-007 | FR-005 | 两个标签页基于同一 revision 保存不同正文 | 后提交收到冲突，两份内容可比较，不能静默覆盖 |
| AT-008 | FR-005 | 服务端提交成功但响应丢失后重试 | 不生成重复逻辑操作，识别已提交或提供冲突处理 |
| AT-009 | FR-005 | 禁用或填满浏览器草稿存储 | 明确提示保障降低，不显示“草稿已保存” |
| AT-010 | FR-005/011 | 同端口更换数据目录，多标签草稿，再恢复备份 | 草稿按实例及会话隔离；新 data_epoch 拒绝旧页面，即使 revision 数值重复也不覆盖 |
| AT-011 | FR-006 | A 上传图片，B 复制引用，删除并永久删除 A | B 正常显示，清理不会删除仍被 B 引用的附件 |
| AT-012 | FR-006/008 | 删除正文图片，但旧历史和回收站引用它 | 查看历史与恢复均正常，附件不能提前清理 |
| AT-013 | FR-006 | 上传成功后撤销、文件提交后 DB 写失败、清理中重启 | 候选可识别，未绑定不自动删，任务幂等恢复 |
| AT-014 | FR-006 | 清理确认与其他页面新增引用并发 | pending_delete 与引用检查协调，不产生失效新引用 |
| AT-015 | FR-008 | 删除父节点含多个后代，再恢复；原父另行删除 | 同批整树恢复，失效父回根并提示，原独立删除批次不误恢复 |
| AT-016 | FR-008 | 修改后查看历史，再恢复旧版本 | 当前内容先留快照，revision 增加，ID 与位置不倒退 |
| AT-017 | FR-007 | 两字中文、中英混合、代码词、百分号及回收站内容查询 | 支持约定字面语义，无 FTS 错误或删除内容泄露 |
| AT-018 | FR-007 | 查询正文非标题词及图表源码词 | 可见文本高亮；无法精确定位时给出源码提示 |
| AT-019 | FR-012 | 插入内部链接，再重命名和删除目标 | 重命名仍跳转；删除显示回收站或失效提示 |
| AT-020 | FR-009 | 导入带父正文、子文档、同名标题和资源的包 | 新 ID 映射正确，正文/树/内部链接/附件保留 |
| AT-021 | FR-009 | ZIP 含 ../、绝对路径、symlink、展开体积或深度超限 | 预检拒绝，不能写到数据目录外或留下半棵树 |
| AT-022 | FR-010 | 导出含 index 正文、同名、非法字符、公式和图表 | 路径唯一安全，另一台断网设备可阅读 |
| AT-023 | FR-011 | 备份时持续编辑、上传与清理 | 写入被维护状态协调，草稿保留，备份内部一致 |
| AT-024 | FR-011 | 在空目录恢复完整备份 | ID、树、正文、历史、回收站、附件和可迁移设置一致 |
| AT-025 | FR-011 | 损坏哈希、缺附件、较新 schema、恢复中磁盘不足 | 不覆盖有效数据，明确原因，回退可用 |
| AT-026 | FR-011 | 升级迁移中断；旧程序打开新 schema | 中断可恢复或阻止写入，旧程序不能破坏新库 |
| AT-027 | FR-004/006 | Markdown/搜索片段含脚本和危险 URL，上传主动内容 | 预览阅读不执行脚本，附件按安全策略提供 |
| AT-028 | FR-001 | 外部 Origin 写请求、非允许 Host、超大请求 | 请求拒绝，合法本机访问不受影响 |

## 10. 测试层次与固定语料

单元测试重点覆盖需要正确性的逻辑：树环与深度、排序、版本校验、Markdown 链接重写、ZIP 路径检查、引用解析和安全净化。不要为简单文案、纯静态样式或镜像实现的低价值逻辑增加测试负担。

集成测试使用真实 SQLite 和临时文件目录，验证事务、触发器、软删除恢复、文件任务、备份恢复及迁移。不能只 mock 数据库后声称已验证 WAL、外键和 FTS 行为。

端到端测试覆盖写作、跨页面切换、上传、草稿恢复、多标签页和导入导出。浏览器卸载与操作系统异常须补充手工故障演练，模拟事件不能等同真实断电。

固定 Markdown 语料至少包含：嵌套列表、任务列表、表格、脚注、重复中文标题、行内 HTML、代码中的标签与符号、公式、Mermaid 流程图和时序图、内部链接、附件链接、中文 URL 及空正文。

导入语料包含本产品资源包和普通 Markdown 包，覆盖文件名大小写碰撞、保留名、重复标题、缺失资源及多层父节点正文。

## 11. 性能目标与容量保护

以下为首版建议目标，基准机配置、实际指标和退化点需记录后再确认发布规模。参考环境为 4 个逻辑核心、8 GB 内存、本地 SSD、当前支持的桌面浏览器。

| 场景 | 建议目标 | 测量条件 |
|---|---|---|
| 启动 | 已有库 readiness 约 5 秒内 | 无迁移，附件不是启动扫描瓶颈 |
| 文档树 | 单库 2,000 节点约 2 秒内可交互 | 不加载全部正文，记录浏览器渲染耗时 |
| 文档保存 | 100 KB 正文常规提交 P95 约 1 秒内 | 不包含自动保存等待时间，独立记录渲染与事务时间 |
| 基础检索 | 10,000 篇、平均 20 KB 正文，P95 约 2 秒内 | 区分 FTS 与中文回退，冷热缓存分别记录 |
| 备份恢复 | 有进度、可估计空间、失败可回滚 | 不以固定秒数承诺任意附件总量 |

数值是目标而非已达成承诺。中文 LIKE 的扫描成本会随内容增长，达不到目标时应优化或明确首版支持规模，不能悄悄取消短词召回。

实施时确定并展示单篇正文、上传文件、导入 ZIP、解压总量、文件数量和查询长度上限。ZIP 限额依据实际解压字节计数，不只信任归档头；深度固定初始最多 32 层。错误需说明当前值和限制，不允许无限消耗内存或磁盘。

## 12. 风险与替代路径

| 风险 | 识别信号 | 处理路径 |
|---|---|---|
| 驱动缺少 FTS5 或备份能力 | 原型失败、发行产物能力不同 | 更换驱动并重复对应平台验证 |
| 编辑与阅读渲染不一致 | 语料锚点、脚注或扩展有差异 | 固定兼容引擎配置，限制未通过的扩展 |
| 中文回退过慢 | 指定规模延迟或阻塞保存 | 优化查询、评估分词或明确容量边界 |
| 单连接长任务阻塞 | 备份/导入时查询与保存超时 | 使用维护提示、短事务、任务化处理，后续再扩池 |
| 文件与数据库不同步 | 孤立文件或缺失引用 | 可重试任务、异常扫描、明确恢复路径 |
| HTML 导出依赖服务 | file 打开缺资源或跨域失败 | 本地脚本或预渲染，重新验收导出承诺 |
| scope 过大 | 原型未闭合就开发协作或 AI | 先完成 P0，后续功能独立排期 |

## 13. 发布检查与结果记录

正式发布前必须完成：

- P0 需求与 AT-001—AT-028 的关联案例均有通过证据，或有明确减少功能范围的文档变更；数据丢失和安全执行风险不能用已知问题备注替代修复。
- 每个声明支持的平台完成单二进制启动、离线功能、中文检索和完整恢复。
- 至少一次使用备份恢复到新目录，与原数据逐项对比，而非在原库上只看文件存在。
- 升级与回退文档说明旧程序兼容边界，迁移失败不会进入正常写入。
- 所有初始容量和失败提示已落实；日志不包含正文和秘密。
- 发布包包含版本、校验和、依赖授权和用户数据目录说明。

执行后将证据放入独立的验收结果文件，避免把本文的要求改写成无依据的“已通过”。建议记录格式：

```text
版本 / 提交标识：
执行日期与平台：
构建依赖和 SQLite 能力：
案例编号 / 操作记录 / 实际结果 / 通过或失败：
性能基准与数据集：
备份恢复对比结果：
已知限制与处理决定：
证据路径：
```

## 14. 文档维护

产品范围改变时先更新需求编号与优先级，再同步架构、接口、交互和验收。参数变更需要说明理由及对已有数据的影响；尚未验证的选择保留“候选”或“待验证”标识。

功能实现完成不自动等于发布就绪，必须核对失败路径和恢复结果。后续增强应复用既有版本校验、回收站、附件引用和备份机制，避免为新功能绕过数据保护。
