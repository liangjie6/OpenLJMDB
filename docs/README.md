## 2. 已统一的设计约定

| 事项 | 本版约定 |
|---|---|
| 产品定位 | 单机、单用户、本地 Markdown 个人知识库，提供语雀式知识库和文档树体验 |
| 技术栈 | Vue 3 + TypeScript + Go + SQLite + Vditor |
| 默认访问 | `127.0.0.1:8080`，本机免登录；局域网访问后续显式设计 |
| 程序发行 | 各平台分别发行单二进制，数据目录独立于程序 |
| 数据来源 | Markdown 为正文权威来源；HTML、检索文本和索引可重建 |
| 编辑模式 | 第一版只开放经验证的 `ir`；阅读为独立只读状态 |
| 自动保存 | 3 秒防抖 + 30 秒最长间隔；串行请求 + revision 乐观锁 |
| 草稿 | IndexedDB，按实例、文档和编辑会话隔离，异常后人工确认恢复 |
| 完整恢复保护 | 保留 instance_id，重新生成 data_epoch，阻止旧页面写入 |
| 删除 | 回收站批次删除及整批恢复，默认不自动清空 |
| 历史 | 每篇默认最多 100 条，5 分钟自动快照窗口，手动与恢复前可强制快照 |
| 附件 | 独立 UUID；当前正文、历史和回收站引用都阻止物理删除 |
| 清理 | 未引用附件先人工确认，pending_delete 状态及可重试任务协调文件删除 |
| 文档树 | 首版新建与删除恢复，深度初始最多 32 层；移动与重排属于 P1 |
| 中文检索 | FTS5 适用词项 + 中文子串 LIKE 回退；真正中文分词先验证再升级 |
| 普通导入 | Markdown / ZIP 预检后整批新增，分配新 ID，同名允许，不覆盖既有文档 |
| 内容导出 | 纯 Markdown 或含资源 ZIP；包内路径与内部链接重写 |
| 完整备份 | 一致数据库快照、附件、历史、回收站、设置、清单与校验和 |
| 默认数据目录 | 系统用户数据目录；可选便携模式与 `--data-dir` |

这些参数是初始设计值，不是性能保证。标题、正文、上传和 ZIP 等限额集中在 02 第 9 节，基准与支持规模在 05 第 11 节验证。

## 3. 相比原方案的主要修订

| 原方案要点 | 修订后的实现要求 |
|---|---|
| 关闭页面时触发保存 | 只能尽力保存，主要依靠正常提交与本地草稿；不能保证退出请求完成 |
| 保存失败等下次输入重试 | 自动有界重试，显示失败和草稿状态；冲突不自动覆盖 |
| 按文档上传目录直接删附件 | 根据跨文档、历史和回收站引用管理，清理与数据库分开协调 |
| 运行时复制目录备份 | 正常退出后可手工复制；在线使用一致快照并暂停协调写入与清理 |
| 只有创建表，无升级流程 | 内置 schema 迁移、升级前备份、失败回退及旧程序兼容检查 |
| Go 渲染与编辑预览天然一致 | 固定版本和语法契约，验证 Lute / Vditor 及公式、图表处理 |
| dist 嵌入即完全离线 | 检查编辑器按需依赖、字体、主题和渲染资源，断网首次启动验收 |
| FTS5 自动支持中文分词 | 明确驱动能力、查询策略及短词回退；分词能力单独做原型 |
| 标题锚点定位所有搜索命中 | 正文高亮与匹配导航，源码命中允许明确降级 |
| 图片导出继续依赖本机路径 | 资源随包携带并改相对路径，脱离应用测试 |
| 密码放 localStorage | 本机默认不暴露网络；后续局域网使用可靠密码验证与会话 |
| 删除只有二次确认 | 补回收站、历史、恢复与永久删除范围说明 |

## 4. 第一版和后续范围

第一版正式可用包括：知识库、基本文档树、编辑阅读、大纲、可靠保存、图片附件、基础搜索、内部链接、回收站、有限历史、Markdown / ZIP 导入、带资源导出、完整备份恢复和升级迁移。

技术原型可以暂缓部分业务功能，但只使用可丢弃测试资料。正式发布不能因为先做体验功能而省去数据恢复能力。

P1 优先增加移动与重排、跨库组织、收藏和编辑体验；P2 再增加标签、反向链接、分词及局域网模式。多人协作、同步、AI、OCR 和全部语雀富文本兼容需要独立定义范围。

## 5. 待原型确认的事项

- SQLite 驱动、FTS5 编译能力、快照 API 和目标平台构建方式。
- Vditor / Lute 的锁定版本、复杂 Markdown 往返与安全配置。
- 中文回退检索在预期个人资料规模下的召回与性能。
- HTML 资源包以文件方式离线打开时的公式和图表能力。
- 支持的操作系统及最低版本、初始容量和导入限额。

上述事项都有 05 中对应的技术验证阶段，不应在未验证前描述成已交付能力。

## 6. 文档变更与使用

需求用 FR 编号追踪，验收用 AT 编号追踪。范围或关键规则变化时同步五份主体文档，避免产品要求、接口协议和界面行为互相矛盾。

01—05 最初交付时仅完成文档结构与链接检查，以及 SQL 示例在本机 SQLite 的可执行性和 FTS 行为检查。当前后端实现与独立验证结果见 06—07；原始设计文档不作为已通过验收的证据，前端及目标平台运行验收仍需后续完成。
