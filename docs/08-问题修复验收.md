## 清空回收站批量删除修复

原先前端先获取每个批次的确认令牌再循环删除。首个文档批次删除会递增知识库树版本、更新时间，使同库后续令牌失效；知识库与此前独立删除的子树还会重复计数。

现使用整体预览和一次清空请求，在单个数据库事务内复用单批次删除逻辑。知识库删除包含的独立子树合并计算；确认后范围变化时整批拒绝，删除中途出错整批回滚。

验证通过：`cd backend && go test ./...`、`cd backend && go vet ./...`、`npm run build`。新增后端回归覆盖同库多个批次、父子批次、整库与独立批次重叠、共享附件保留、51 个批次、失效确认及中途出错回滚。隔离数据的浏览器流程验证取消不删除、6 个混合批次仅发一次 DELETE、确认后新增批次整批拒绝、51 个批次全部清空；页面异常为零。

## 导入逐篇位置与自动分类

Markdown 预检后可以逐篇指定一个知识库和可选父文档，也可统一应用位置。
跨知识库批次共享文档新 ID 和链接映射，以一个事务提交，任意文档失败整批回滚。
提交前及事务内校验各目标知识库树版本、父节点、节点数量与深度，按库更新树版本。
结果未确认时保留原正文和幂等键，禁止改位置或重新选文件，重试查询原批次。

设置增加默认关闭的“导入自动分类”开关，保存并重启后仍保留。
开启时将完整 Markdown 标题、正文和现有知识库名称、描述发送至决策模型，
使用 `choice` 的最高选项概率选择一个知识库，不设置信度阈值。
自动结果可逐篇修改，接口失败或未配置密钥时可以继续手动导入。
停止分类或离开页面后取消在途请求，迟到的结果不会覆盖人工选择。
ZIP 不调用模型，继续按整包目标导入并保留父子结构。

默认服务根地址为 `https://<CLASSIFIER_HOST>`，模型为 `decision-model-preview`。
密钥通过后端环境变量 `LJMDB_DECISION_API_KEY` 提供；
`deploy/configure-classifier.sh` 隐藏输入密钥并配置现有 systemd 服务的 EnvironmentFile。
密钥不写入数据库、前端或项目文件，设置接口仅返回是否已配置。
