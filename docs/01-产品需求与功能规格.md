# 产品需求与功能规格

版本：v1.0（待实施设计）  
日期：2026-10-04  
适用产品：本地 Markdown 个人知识库  
实现技术：Vue 3、TypeScript、Go、SQLite、Vditor

## 1. 产品定位与范围

本产品面向在个人电脑上长期积累资料、编写笔记、整理项目文档的用户，提供接近语雀的知识库组织、文档树和浏览器编辑体验。正式版本无需互联网或外部账号，可按操作系统发行一个包含前端资源的可执行文件；数据库和附件保存在本机。

正文以 Markdown 为唯一权威来源。编辑器显示、阅读页面、HTML 缓存、搜索索引和导出文件均由它生成或转换；标题、树结构和时间等元数据单独保存。复杂版式的表达能力受 Markdown 限制，不承诺与语雀所有富文本内容完全互通。

本方案区分“验证原型”和“第一版正式可用”。原型可以暂缓实现部分功能以验证技术路线；面向长期真实资料的正式发布必须完成草稿恢复、冲突保护、回收站、有限历史、备份恢复和数据库迁移。

| 范围层级 | 必须具备的能力 |
| --- | --- |
| 技术验证原型 | 离线编辑与渲染、中文检索样例、目标平台构建、数据写入与读取 |
| 第一版正式可用 | 知识库与文档树、稳定编辑、可靠保存、附件、检索、回收站、历史、导入导出、备份恢复、版本升级 |
| 后续迭代 | 拖拽排序、跨知识库移动、收藏、更多编辑模式、标签、反向链接、显式局域网访问 |

## 2. 目标用户与核心任务

### 2.1 目标用户

- 个人学习者：将课程笔记、代码示例、图片和公式组织为分层文档。
- 开发者与研究人员：离线记录方案、实验过程和项目资料，能快速检索正文。
- 重视本地数据的用户：可以检查数据位置、备份、迁移和导出，不依赖云服务。

### 2.2 用户任务

| 任务编号 | 用户任务 | 完成条件 |
| --- | --- | --- |
| UT-01 | 第一次启动并创建知识库 | 浏览器可进入首页，创建后能立即编写文档 |
| UT-02 | 连续记录笔记并插入图片 | 保存状态明确，重新打开后正文和图片完整 |
| UT-03 | 按主题组织父子文档 | 新建、重命名和展开折叠可用，父文档本身可以有正文 |
| UT-04 | 查找过去写过的内容 | 可按标题或正文搜索，并打开和定位匹配内容 |

## 4. 页面结构与使用流程

首页展示有效知识库，包含名称、描述、有效文档数量和最后更新时间；提供新建、全局搜索、回收站、导入及设置入口。空数据状态应引导创建知识库或导入资料，不使用默认示例内容覆盖用户资料。

主工作区采用左侧知识库切换器和文档树、中间标题与编辑区、右侧可折叠大纲的布局。当前文档高亮；未保存、失败或冲突状态与树节点对应。展开状态和大纲显隐可在浏览器本地记忆，不作为正文的一部分。

编辑与阅读有明确入口。阅读模式禁止修改正文，任务列表复选框也不产生隐式写入；编辑模式允许修改。阅读页面保留复制内部链接、搜索和导出入口。

全局搜索可以从首页或工作区打开，显示知识库名称、文档标题和匹配片段。回收站、历史版本、备份管理等高影响操作页面显示操作对象和影响范围，避免仅使用泛化的“确定吗”。

## 5. 知识库与文档组织

### 5.1 FR-002 知识库管理

用户可以创建知识库、修改名称和描述。名称不能为空；去除两端空白后进行校验，但保留正文和描述中有意义的空白。知识库通过稳定 ID 识别，同名知识库可以存在，列表应提供描述与时间帮助区分。

文档数量只统计未进入回收站的文档。新增、正文保存、重命名及树结构变化更新知识库最后活动时间，单纯浏览不更新。列表按确定规则展示，例如最后活动时间倒序，并以 ID 打破并列。

删除知识库表示整库移入回收站，包括文档树、历史和附件引用；确认窗口展示知识库名称和受影响文档数量。删除成功后不再出现在正常列表、搜索和导出选择中。

### 5.2 FR-003 文档树

每篇文档属于一个知识库，有稳定 ID，可有一个父文档。根文档父 ID 为空；所有节点都允许同时拥有正文和子文档。初始最大深度为 32 层，根节点记为第 1 层；超过限制时拒绝操作并说明原因，后续可调整该保护值。

首版支持新建根文档、新建子文档、新建同级文档、重命名、展开折叠、进入文档和删除子树。新文档默认标题“无标题”，追加到目标同级列表末尾。同名文档允许存在，路由和内部链接不能依赖标题唯一性。

树列表仅加载组织所需的元数据，不附带全部正文。后端保证父节点存在、父子属于同一知识库、结构无环、同级排序稳定；即使前端误提交数据也不能产生损坏的树。

拖拽、任意重新挂接和跨知识库移动留至 FR-013。后续移动必须校验整个子树移动后的最大深度，以一个事务更新父节点和排序；不能将文档移动到自己或自己的后代中。

## 6. 编辑、阅读与渲染

### 6.1 FR-004 编辑能力

首版先交付 Vditor 一个经过验收的编辑模式，建议采用即时渲染模式。另两种模式在内容往返测试通过后加入。工具栏至少支持标题 H1—H6、粗体、斜体、删除线、列表、任务列表、引用、代码块、表格、链接、图片、分隔线和撤销重做。

Markdown 扩展至少覆盖 GFM、脚注、行内及块级公式、Mermaid 流程图与时序图、代码高亮。大纲从当前正文标题生成，编辑时刷新，点击能跳到对应标题；重复标题生成不同锚点。

标题为独立字段，不自动从正文第一行推导，也不强制同步为正文 H1。标题与正文使用相同保存保护，避免从树中重命名覆盖另一页的最新正文。

### 6.2 渲染约束

编辑预览、阅读和导出遵循相同 Markdown 语法契约及版本。HTML 只是可重建缓存，修改渲染器后允许重新生成；不能以缓存 HTML 反向覆盖源 Markdown。

公式、Mermaid、字体、编辑器样式和高亮资源随程序本地提供，首次打开也不能依赖 CDN。外部链接可以存在；用户手动引用外部图片时显示外部资源属性，离线可用承诺仅覆盖已存入本地的资源。

允许的内联 HTML 必须经过过滤，脚本和危险 URL 不能执行。上传 HTML 等可执行内容作为下载附件处理。语法错误的公式或 Mermaid 保留源码并给出可理解提示，不让整篇文档无法打开。

## 7. FR-005 保存与恢复语义

### 7.1 自动保存

输入停止 3 秒后触发保存；持续输入时，首次未保存修改起最长 30 秒触发一次保存。手动保存立即请求；切换文档前尝试完成保存，同时保证草稿已记录。离开页面时发送保存仅作为补充，不能依赖浏览器关闭事件保证成功。

同一编辑会话内保存请求必须串行。每次请求包含捕获时的标题、正文与基础 revision；用户在保存过程中继续输入时，成功回应仅标记该快照已保存，随后继续保存更晚的修改，不能将整个编辑器误标为已保存。

界面至少区分“已保存”“未保存”“保存中”“保存失败，正在重试”和“存在版本冲突”。显示最近成功保存时间。网络或临时服务故障采用有上限的退避间隔自动重试，不以新的输入作为重试前提；校验错误和冲突不自动无限重发。

### 7.2 本地草稿

编辑时将未提交快照写入 IndexedDB，草稿包含数据集合 instance_id、文档 ID、编辑会话 editor_session_id、基础 data_epoch、标题、Markdown、基础 revision 和本地更新时间。每个标签页保留独立草稿，不能用同一个文档主键互相覆盖。数据库不可用、磁盘满等浏览器存储错误必须显示，不能继续声称草稿已经安全保存。

再次打开时检测草稿，与后端当前版本比较。用户可以查看草稿并选择恢复到编辑器、保留为新文档或丢弃；恢复草稿不立即静默覆盖服务器。保存成功后只清理已确认提交的草稿版本，不删除正在编辑的更新草稿。

浏览器存储只是异常恢复辅助，可能被清除，不替代完整备份。对于尚未保存的内容，应用不能承诺在浏览器强制终止、系统故障和存储错误的所有组合下零丢失。

### 7.3 多标签页冲突

服务端通过 revision 乐观锁比较保存基线。版本过期时返回 HTTP 409，并返回可用于比较的当前版本信息；不接受后到请求静默覆盖。

冲突页面展示本地内容和服务端当前内容，允许复制本地内容为新文档、重新载入或比较后明确提交。任何明确覆盖也必须以最新 revision 重新校验；若期间又有更新，继续提示冲突。已进入回收站的文档不能被旧页面保存而自动复活。完整恢复后生成新的 data_epoch，旧页面写入被拒绝，防止恢复后的 revision 数值复用导致旧内容误覆盖。

## 8. FR-006 图片与附件

图片支持粘贴、拖入编辑器和文件选择上传；其他附件通过文件选择上传并插入下载链接。上传显示进度与失败状态，失败时保留原有正文，不能留下看似成功的失效引用。

附件使用独立稳定 ID，与上传时的文档目录解耦。原始文件名用于显示，存储名称由随机 ID 等不会冲突的机制生成。一个附件可被多篇文档、历史版本和回收站内容引用；复制含图片的正文后，两篇文档都能显示图片。

附件上传成功不等于正文保存成功。用户撤销插入、关闭页面或保存失败可能产生未绑定附件。首版不自动物理删除这些文件，管理页列出候选、大小和产生时间，人工确认前再次校验引用。

只要当前正文、任一保留历史或回收站中存在引用，就禁止删除该附件。永久删除文档不直接递归删除上传目录；资源清理单独完成，禁止将上传归属当作唯一引用关系。

上传前后检查容量、文件名和实际类型，明确反馈超限及空间不足。附件尺寸限额、总空间策略作为实施配置给出；正式发布需在界面展示限制。未知类型按下载处理，不允许同源执行任意用户附件。

## 9. FR-007 检索

搜索默认覆盖全部有效知识库，可缩小到当前知识库。首版支持标题和正文关键词检索，默认排除回收站与历史；查询不能为空，查询长度和分页数量有明确上限。

初始实现使用 FTS5 处理适合其 tokenizer 的英文及词项，中文短词和 FTS 无法可靠覆盖的中文查询以参数化 LIKE 等子串方式兜底。百分号、下划线等输入按文字检索，而非意外成为通配符；后端不直接将用户输入当成 FTS 表达式。

首版中文能力定义为基础关键词及子串检索，不宣称完成语言学分词、语义搜索或同义词理解。中文分词方案须通过原型验证后再升级，升级后可以从权威正文重建全部索引。

结果包含知识库、标题、更新时间和匹配片段，标题命中优先。高亮以安全文本标记实现，不能把搜索片段当作任意 HTML。点击结果打开文档后高亮关键字，支持上一个/下一个匹配；任意正文命中不依赖标题锚点定位。

若阅读渲染中没有可定位文本，例如命中仅出现在图表源码或 URL，提示匹配来自源码并提供查看入口。不能承诺所有 Markdown 源字符都能在阅读页面直接滚动定位。

## 10. FR-008 回收站与历史

### 10.1 删除与恢复

删除文档默认将整棵子树作为一个删除批次移入回收站，保留 ID、原父关系、原排序、正文、历史和资源引用。确认窗口显示包含当前节点的文档总数。默认不自动清空回收站。

恢复按删除批次恢复完整子树。如果原父节点有效，则恢复到该父节点下；原父已不存在或仍在回收站，则恢复为原知识库根节点并提示位置变化。原知识库在回收站时先恢复知识库；永久删除的知识库不能成为恢复目标。

知识库整库删除和文档删除分开显示；同一批次不重复计数。恢复只恢复该批次中删除的内容，不自动恢复此前已单独删除的其他批次。永久删除和清空必须展示不可恢复的对象、数量并要求明确确认。

### 10.2 有限历史

历史以已成功保存的标题和 Markdown 快照为基础，每篇文档默认最多保留 100 个历史版本，可配置上限。自动保存不必每次生成历史，但正式实现需明确合并规则、定期快照和手动保存边界，避免持续写作没有恢复点。

用户可查看历史时间、标题及正文，与当前版本比较并恢复。恢复作为一次新的写入，执行 revision 校验并保留恢复前版本；不能直接把 revision 倒退。历史只恢复标题和正文，不倒退文档 ID、知识库和树位置。

删除较旧历史时同时更新资源引用，仍被其他有效对象引用的附件保留。浏览器编辑器的撤销重做只作用于当前会话，不能作为历史版本的替代。

## 11. FR-009 导入

首版提供单篇 `.md` 导入和 Markdown 加资源 ZIP 导入。导入前选择目标知识库及可选有效父节点，展示识别出的文档数量、资源数量、总大小及异常。保留文档正文，依据文件名推导独立标题；通用文件中的首个 H1 保留，不自动删除。

通用 ZIP 根据目录关系生成文档树，本产品导出包优先依据 manifest 还原。资源相对路径转换为本地附件引用；内部文件链接能解析时转换为新文档 ID 链接。重新导入内容包分配新 ID，不与现存对象进行隐式覆盖。

通用 ZIP 的所有文件均位于同一个外层目录且该目录没有 index.md / index.markdown 时，外层目录只作为打包容器，不生成空白文档；内部子目录关系保留。资源目录不生成文档，预览的资源数量来自实际附件列表，文档深度和缩进按父子关系计算。预检提示和导入报告默认折叠，可展开或收起。

ZIP 内文件名优先按 UTF-8 读取；未声明 UTF-8 且不是有效 UTF-8 的文件名兼容 GBK，解码后执行路径安全和重复路径校验。Markdown 正文仍要求 UTF-8。无效文件名编码单独提示，不归为危险路径。

冲突名称允许保留，导入报告列出完整路径。缺失图片、不能识别的内部链接和不支持内容需提示，不以“成功”掩盖；外部 URL 保留，首版不自动下载远程资源。

导入包拒绝路径穿越、越界路径、符号链接和异常解压体积。导入分为解析校验、预览、提交阶段；失败时回滚本批次数据库变更，暂存文件可重试清理，不留下可见的半棵文档树。

## 12. FR-010 内容导出

| 导出类型 | 包含内容 | 使用场景 |
| --- | --- | --- |
| 纯 Markdown | 当前正文和标题表达约定 | 用户只需要文本；本地附件不保证随单文件可用 |
| 单篇资源 ZIP | Markdown 或 HTML、引用资源、清单 | 离开应用后阅读或迁移一篇文档 |
| 知识库 ZIP | 有效文档树、Markdown、引用资源、清单 | 内容交换、迁入其他工具 |
| HTML 资源 ZIP | 可直接打开的 HTML、样式及必要资源 | 在另一台断网电脑阅读 |

正式版默认提供带资源选项并清楚标明纯 Markdown 的限制。导出不得将图片继续指向本机 HTTP 地址。标题与正文均保留；通过导出清单区分独立标题和正文内容，避免反复导入增加重复标题。

纯 `.md` 文件在原正文前增加独立标题 H1，不删除原正文中的 H1，适合文本阅读交换；元数据保真回导使用资源 ZIP，ZIP 内正文保持原样、标题由清单保存。跨出本次导出范围的文档链接与网络图片列入依赖报告，离线可跳转承诺只覆盖包内目标和本地资源。

父节点有正文也有子文档时使用目录内 `index.md` 等确定结构。同名文件、系统保留名、非法字符和路径过长均映射到唯一安全路径，清单保存原始名称和层级；根据该映射重写内部文档链接与附件相对路径。

HTML 导出必须在断网环境打开验收。公式和 Mermaid 可以预渲染，或随包提供必要资源；仅内联 CSS 不算完成离线支持。知识库内容导出默认不包含回收站、历史、全局设置和草稿。

## 13. FR-011 备份、恢复与升级

内容导出服务于阅读和格式交换；完整备份服务于恢复整个应用状态。完整备份包括一致的数据库快照、全部应保留附件、必要设置及版本清单，保留原始 ID、历史和回收站。浏览器 IndexedDB 草稿不属于后端完整备份，创建备份前提示存在未保存编辑。

应用完全退出后可以复制整个数据目录；运行中必须使用内置一致性备份，不允许界面建议直接复制活跃数据库文件。备份完成后生成校验信息，报告数据库与附件数量、大小和遗漏；磁盘空间不足时明确失败。

恢复先验证格式、校验和、数据库完整性、附件存在性和版本兼容性，并展示预览。确认后暂停售写，在暂存目录验证成功后切换；替换现有数据前保留可回滚副本。校验失败不覆盖当前数据，现有浏览器会话和草稿重新比较版本后才能继续编辑。首版由后台关闭并重开数据库完成恢复，浏览器必须重新加载；不要求自动重启操作系统中的应用进程。

应用启动自动识别 schema 版本并执行受控迁移。升级前建立可回滚备份，失败时中止服务写入并提示恢复路径；较旧程序遇到较新 schema 必须拒绝写入。用户无需运行 SQL，但应用必须维护迁移脚本及版本记录。

## 14. FR-001 与 FR-012 运行和链接

默认仅监听 `127.0.0.1:8080`，本机免登录，启动成功后尝试打开浏览器并显示实际地址。端口占用、重复启动、数据目录不可写、数据库损坏均有清楚错误和处理入口，失败时不悄悄初始化另一套空数据。

默认数据目录使用系统用户数据目录，提供便携模式和 `--data-dir`。用户能在设置或启动输出找到实际路径。各目标平台分别构建发布程序；单二进制指程序分发形式，数据库、附件和备份仍独立存在。

内部文档链接包含稳定文档 ID，提供搜索并插入链接、复制链接的基础入口。重命名不影响跳转；后续移动也保留 ID。目标进入回收站时显示恢复提示，永久删除时显示目标不可用，不能错误指向同名新文档。

局域网访问属于后续显式模式，启用时需要绑定地址、认证会话和全部资源访问控制设计；默认版不通过更改监听地址悄悄成为无认证的网络服务。

## 15. 非功能目标与验收边界

以下性能是待测目标，不是已经验证的承诺。建议统一基准环境为 4 核 CPU、8 GB 内存、SSD、单本机用户，在发布说明中记录操作系统、浏览器、构建方式和样本生成规则。

| 验收项 | 初始目标与测试条件 |
| --- | --- |
| 首次启动 | 无需联网，5 秒内进入可用首页；浏览器启动耗时另行记录 |
| 文档树 | 单库 2,000 节点只读取元数据，2 秒内展示可操作树 |
| 普通编辑 | 100 KB 正文输入无持续卡顿，保存状态在正常接口响应后及时更新 |
| 检索 | 总计 10,000 篇、约 200 MB 文本，普通查询首屏目标 2 秒内；中文兜底单独测量 |
| 数据可靠性 | 确认成功的写入重新启动后可读，失败和冲突不静默覆盖 |
| 离线资源 | 全新浏览器会话断网后可编辑、阅读公式和图表、访问本地附件 |
| 可迁移性 | 带资源导出在断网新机器可读，备份恢复后 ID、树、历史和回收站一致 |

若中文 LIKE 兜底在目标数据集超过性能目标，应在正式发布前明确支持规模、改善查询或调整方案，不能把原型的小数据表现直接当成规模能力。

## 16. 发布前必须通过的业务场景

- 持续输入超过 30 秒且没有暂停，仍出现成功保存；保存中继续输入，最后内容不丢失。
- 模拟保存失败后停止输入，自动重试仍工作；关闭并重开后可选择恢复本地草稿。
- 两个标签页修改同一篇文档，旧 revision 被拒绝，两个版本都可保留和查看。
- 将带图片正文从 A 复制到 B，再删除 A 或清理 A 的历史，B 仍可显示图片。
- 删除有多层子文档的父节点，搜索不返回已删文档；恢复后内容、层级和资源可用。
- 正文误覆盖后恢复历史，恢复前版本仍可查，树位置和稳定链接保持正确。
- 导入含缺失资源或危险路径的 ZIP，报告可理解；失败不留下部分可见文档。
- 带资源导出在另一台断网电脑可打开，内部链接、图片、公式和图表均可用。
- 在运行时创建备份并恢复到独立目录，对比文档、历史、回收站和附件完整性。
- 以旧版数据启动新版迁移，模拟迁移失败后可回滚；旧程序不得写入新 schema。

对应技术细节、状态模型、接口与测试步骤由后续文档展开；实现时应以以上需求编号建立追踪，任何正式版删减都应同步更新范围和验收条件。
